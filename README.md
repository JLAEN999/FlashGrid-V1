## 📖 项目简介

**闪阵 FlashGrid** 是面向 ESP32 开发、设备调试和小批量生产的 Windows 桌面工具，将**多设备烧录**与**串口调试**放在同一款软件中。

在“烧录”页面配置端口、固件及地址，可为多台设备启动并行任务；在“串口调试”页面查看设备原生输出、发送命令，并在设备掉线后等待自动重连。工业浅色仪表台集中显示烧录数量、成功率和各路设备状态，方便快速定位失败任务。

**本仓库为软件发布与文档仓库，应用主代码暂不公开。** 本文所称“半开源”指使用说明、版本记录等材料公开，不代表应用主代码采用开源许可证。第三方组件适用各自的许可证。

## ✨ 功能特性

### 🔥 多设备批量烧录

| 功能 | 说明 |
|---|---|
| 8 路烧录通道 | 可选择、启用多个串口，为不同端口启动并行烧录任务 |
| 独立进程执行 | 每个端口的 esptool 调用在独立进程运行，隔离输出及运行状态 |
| 多固件配置 | 最多 8 项固件，每项可配置路径、写入地址与是否启用 |
| 芯片选择 | 支持自动识别，或从已提供的 ESP32 系列型号中手动选择 |
| 擦除选项 | 支持单端口擦除、烧录前擦除 |
| 烧录参数 | 可选择波特率、Flash 模式及频率 |
| 自动烧录 | 启用后，按已配置的有效固件处理新检测到的设备 |
| 端口占用保护 | 跳过同一端口的重复任务；烧录前停止对应串口调试连接 |
| 记录导出 | 展示烧录时间、端口、MAC、芯片及结果，并支持导出 |

界面提供的芯片选项：ESP32、ESP32-S2、ESP32-S3、ESP32-C2、ESP32-C3、ESP32-C6、ESP32-H2、ESP32-P4。具体板卡能否烧录仍取决于驱动、接线、固件、启动模式及烧录参数，不能将型号选项视为所有板卡已完成实测认证。

### 🖥️ 工业浅色仪表台

- 浅灰工作区、深蓝主按钮与白色状态卡。
- 展示累计烧录数、成功数、失败数与成功率。
- 8 路设备卡显示当前配置的端口及任务状态。
- 状态随连接设备、识别芯片、擦除、写入校验和最终结果更新；成功以绿色、失败以红色突出显示。
- “烧录”和“串口调试”双页签，分别组织生产操作与日常调试。

### 📟 串口调试与原生日志

| 功能 | 说明 |
|---|---|
| 原生文本输出 | 按 UTF-8 连续解码接收数据，保留设备自己的换行，不为每个读取分片插入时间戳或 RX 前缀 |
| 独立端口接收区 | 每个监听端口单独显示，避免多设备日志混在一起 |
| 串口参数 | 支持波特率、数据位、校验位与停止位设置 |
| 文本 / HEX 收发 | 可选择 HEX 显示、HEX 发送及发送 CRLF |
| 关键词检测 | 检测接收文本中的关键词，匹配结果显示在状态栏；支持关键词跨读取分片到达 |
| 复制与保存 | 接收区支持右键菜单、复制、粘贴、剪切、全选及保存当前文本 |
| 动态快捷命令 | 支持新增、编辑、删除与滚动，不再限制为 8 条；修改后自动保存 |
| 自动重连 | 掉线后每约 100 ms 尝试重连；实际恢复时间还取决于驱动与系统枚举 |

**关键词命中仅用于提示，不会改变烧录成功或失败的统计结果。** 接收区可编辑，手动修改的内容也会进入“保存接收”导出的文本。

## 📦 下载与启动

### 推荐：下载 Windows 便携包

1. 打开 [最新 Release](https://github.com/JLAEN999/FlashGrid-V1/releases/latest)。
2. 在 **Assets** 中下载 **`FlashGrid-V1-Windows-x64.zip`**。
3. 将整个压缩包解压到有写入权限的文件夹。
4. 双击 **`FlashGrid-V1.exe`** 启动，无需安装 Python 或手动安装 Python 依赖。
5. 连接设备，并根据板卡实际使用的 USB 串口芯片安装相应驱动。

> GitHub 自动生成的 **Source code (zip / tar.gz)** 只包含本仓库的公开文档，不包含应用主代码，也不是软件安装包。请下载名称中带 **Windows-x64** 的附件。

面向 Windows 10/11 x64 使用。当前版本已在开发用 Windows 环境检查启动和界面；不同系统、驱动、板卡和 USB 集线器仍需实测。首次启动会解压内置运行库，请等待窗口出现。

Release 同时提供 `SHA256SUMS.txt`，用于核对下载包的 SHA-256。可在 PowerShell 中执行：

```powershell
Get-FileHash .\FlashGrid-V1-Windows-x64.zip -Algorithm SHA256
```

## 🎮 使用指南

### 1. 烧录单台设备

1. 连接设备，在“烧录”页点击“刷新列表”。
2. 选择一个串口并勾选该通道；不使用的通道取消勾选。
3. 勾选需要写入的固件，点击“浏览”选择文件，填写**该固件实际要求的地址**。
4. 选择芯片型号或“自动检测”，设置烧录波特率、模式和频率。
5. 确认配置后点击“开始烧录”，查看设备状态卡及日志窗口。
6. 在右侧烧录记录中核对 MAC、芯片和最终结果。

**烧录地址以固件发布者或工程构建产物给出的配置为准。** 合并固件与分区固件的写法不同，不要直接照搬其他板卡的地址。擦除 Flash 会清除设备原有数据，使用前请确认需要保留的数据已经处理。

### 2. 批量烧录多台设备

1. 为每台设备选择**不同的串口**，勾选需要工作的通道。
2. 确认这些设备适用同一组固件及参数；不同固件需求请分批处理。
3. 点击“开始烧录”，各端口分别执行任务。
4. 通过状态卡定位失败通道，再查看对应日志；批次完成后可导出记录。

如遇并行烧录不稳定，可先减少同时连接的设备、降低烧录波特率，并检查 USB 集线器供电和数据线。不要让其他串口工具同时占用这些端口。

### 3. 自动烧录与烧录后监听

- **自动烧录**：先配置有效固件、地址及参数，再启用。新检测到的设备可能直接触发写入，请只连接准备烧录的设备。
- **烧录后监听**：先设置日志波特率和可选关键词，再勾选。任务成功后启动对应端口的串口日志监听。
- **监听选中端口**：可从烧录页为已选择且启用的端口启动监听。
- **停止监听**：关闭正在监听的串口，同时停止它们的重连等待。

烧录波特率与日志波特率是不同设置；设备运行日志通常由固件决定，应以实际固件参数为准。

### 4. 串口调试

1. 切换到“串口调试”页，选择端口及正确的串口参数。
2. 点击“打开串口”，在对应端口的接收页签查看日志。
3. 需要时填写检测关键词；检测作用于正在接收的端口。
4. 在发送框输入内容，按协议选择文本或 HEX、是否附加 CRLF，然后点击“发送”。
5. 点击“保存接收”导出当前接收区文本；点击“关闭串口”停止该串口及自动重连。

HEX 发送输入示例：`01 03 00 00 00 02`。如果协议要求精确字节长度，请确认是否需要关闭“发送新行(CRLF)”。

### 5. 快捷命令与复制粘贴

- 点击 **“＋ 新增命令”** 增加一条，直接编辑对应输入框。
- 点击左侧编号按钮，将该条命令发送到当前选择的串口。
- 点击右侧 **“×”** 删除命令，其余条目自动重新编号。
- 命令较多时滚动查看；命令会保存到软件同目录的 `快捷命令.json`。
- 日志区支持 `Ctrl+C`、`Ctrl+V`、`Ctrl+X`、`Ctrl+A` 和右键菜单。

### 6. 设备断电与自动重连

打开串口后保持监听即可，无需在设备每次上电后手动重新打开：

- 目标设备断电，但 USB 转串口模块仍在线：连接会继续保持，等待新的设备输出。
- 串口消失或读取报错：软件等待设备恢复并自动重连。
- 存在唯一 USB 标识：可跟踪同一设备重新枚举后的 COM 号；标识不明确时不会猜测其他设备。
- 手动关闭串口，或开始相应端口的烧录 / 擦除：停止原监听与重连，避免争用串口。

**自动重连不能补回连接恢复之前已经输出的日志。** 要尽可能完整捕获最早开机输出，建议让外接 USB 转串口模块持续供电，仅切换目标设备电源，并确保串口参数一致。

## 🔧 常见问题

| 问题 | 建议排查方式 |
|---|---|
| 找不到串口 | 检查驱动、数据线和设备管理器；点击刷新；必要时检查“只看 USB 串行设备”的过滤设置 |
| 提示端口被占用 | 关闭其他调试工具、旧版本 FlashGrid 或占用同一端口的任务 |
| 烧录连接失败 | 检查芯片选择、BOOT / 下载模式、供电及接线，参考板卡进入下载模式的方法 |
| 多台设备只有部分成功 | 对照每路日志检查失败原因；降低波特率、减少并发数量，检查 USB 供电与线材 |
| 日志乱码或无输出 | 核对日志波特率、数据位、校验位和停止位；当前文本接收按 UTF-8 解码，非文本数据可用 HEX 查看 |
| 开机最早几行仍缺失 | 自动重连存在系统枚举窗口；保持外接 USB 转串口模块在线，提前打开监听后再给目标设备上电 |
| 命令没有响应 | 核对当前发送端口、命令格式、文本 / HEX 模式，以及是否需要 CRLF |
| 快捷命令未保存 | 检查软件所在目录是否可写；不要直接在压缩包内运行 |
| 接收文本很大、界面变慢 | 当前接收区不自动裁剪旧日志；长时间运行时可先保存再清空接收区 |
| 找不到源码或编译步骤 | 本仓库不提供应用主代码，当前只提供 Windows 发布包、文档及问题反馈入口 |
